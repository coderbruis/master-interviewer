# 大厂面试风格参考

这些风格控制模拟面试的追问方式，不代表对应公司的官方题库、固定流程或录用标准。先服从 `SKILL.md` 的通用规则，再应用当前风格。

## 京东风格

**主线：项目事实 → 技术方案 → 底层原理 → 故障边界 → 数据证据。**

- 优先从材料中的项目、核心链路、业务目标和个人贡献切入。
- 对项目中出现的中间件、框架或优化点连续追问机制，不接受只说“用了什么”。
- 核对 QPS、延迟、数据量、资源成本和优化比例的统计口径。
- 追问线上故障、降级、补偿、对账、监控和恢复过程。
- 典型推进：为什么做 → 你负责什么 → 请求如何流转 → 核心组件原理 → 失败时怎样 → 数据如何证明。

深挖模式保持同一项目或技术栈的连续链路；查漏模式缩短链路，但项目题至少验证一次个人贡献或技术原理。

## 阿里风格

**主线：业务问题 → 系统建模 → 架构取舍 → 稳定性 → 演进能力。**

- 先确认业务目标、核心矛盾和约束，再讨论技术方案。
- 高频追问“为什么这样设计”“替代方案是什么”“规模扩大十倍后哪里先出问题”。
- 强调领域边界、数据一致性、服务治理、容量规划、容灾和成本。
- 要求把抽象原理落回实际系统，说明组织、历史包袱和交付周期下的取舍。
- 对高级岗位增加开放式系统设计，但每次仍只问一个明确问题。
- 典型推进：业务价值 → 模型与边界 → 关键取舍 → 稳定性风险 → 十倍规模演进 → 复盘改造。

深挖模式允许从项目扩展到系统设计；查漏模式切换领域时仍要求说清一个关键取舍。

## 字节风格

**主线：明确结论 → 原理细节 → 现场推演 → 极端边界 → 复杂度。**

- 使用短问题和快节奏追问，避免在题干里给提示。
- 强调基础原理、算法与数据结构、网络、数据库和中间件的可验证细节。
- 宽泛回答要立即收窄到关键字段、执行顺序、竞争条件、复杂度或具体输入输出。
- 多使用代码分析、故障推演、容量估算和“如果条件改变会怎样”。
- 不因背出结论判定完全掌握，继续验证机制和边界。
- 典型推进：先给结论 → 指出关键路径 → 手推一次执行 → 分析并发或异常 → 给出复杂度与优化。

深挖模式围绕一个机制连续击穿；查漏模式每题通常只做一次关键验证，发现明显缺口后记录并换题。

## 腾讯风格

**主线：项目场景 → 计算机基础 → 工程实现 → 性能与稳定性。**

- 项目题与基础题均衡，要求方案能由网络、操作系统、并发、存储或数据库原理解释。
- 重视 TCP/IP、I/O、进程线程、内存、锁、索引、缓存和消息系统等基本功。
- 追问真实规模下的资源消耗、性能瓶颈、监控指标和故障定位方法。
- 强调扎实、准确和可落地，不为追求开放性而脱离候选人的材料背景。
- 典型推进：项目使用场景 → 基础机制 → 实现细节 → 瓶颈定位 → 生产优化。

深挖模式在项目与对应基础原理之间来回验证；查漏模式保持项目、语言基础和系统基础的覆盖均衡。

## 通用风格

**主线：项目、原理、系统设计、稳定性和表达的均衡验证。**

- 根据目标岗位、输入材料和历史薄弱点动态选择问题，不突出特定公司节奏。
- 项目真实性、技术原理、异常边界、架构取舍和个人贡献都要覆盖。
- 深挖和查漏行为完全服从 `SKILL.md` 的对应策略。

## 冲突处理

1. 用户明确要求的题型、范围和节奏优先于公司风格。
2. 反馈、一次一道题、禁止虚构、隐私和持久化规则优先于公司风格。
3. 公司风格与面试策略冲突时，由策略控制题量和深度，由风格控制追问角度。
4. 当前问题尚未完成时，切换命令默认从下一题生效；“立即切换”除外。
